# UX-редизайн карты маршрута

**Дата:** 2026-05-06
**Затронутый компонент:** `frontend/Task Planning App/src/app/components/MapView.tsx` и связанные модули
**Картографический движок:** Yandex Maps JS API 2.1 (без замены)

---

## 1. Проблема

На карте оптимизированного маршрута визуальные элементы перекрываются:
- Numbered-маркеры задач, плашки расстояния/времени и иконки транспорта рендерятся как отдельные `Placemark` с пресетами `islands#blueCircleIcon` / `islands#grayStretchyIcon` без управления z-index
- Совпадающие или близкие координаты (несколько задач по одному адресу — частый случай) сливаются в один маркер с текстом `"1,2"` или `"…"` — нечитаемо при 3+ задачах
- Плашка сегмента содержит только время (`legDuration`) без иконки транспорта, а в режимах `pedestrian/auto` нет панели деталей
- Линии маршрута не различаются стилем по типу перемещения — только цветом
- Нет легенды

## 2. Цель

Сделать визуальное представление маршрута читаемым во всех режимах (pedestrian / masstransit / auto) без замены движка карты, без изменений API и алгоритма оптимизации.

## 3. Принятые архитектурные решения

| # | Вопрос | Выбор | Альтернативы (отвергнуто) |
|---|---|---|---|
| 1 | Совпадающие координаты | **Stack** — вертикальный стек маркеров над реальной точкой с короткой ножкой | Spiderfy (раскрытие по клику), Cluster (по зуму) — добавляют скрытое состояние, на маршруте 5–30 точек кластеризация бесполезна |
| 2 | Размещение плашек сегментов | **Hybrid B** — простая плашка на середине сегмента + панель деталей снизу | Полноценный pixel-bbox anti-overlap с leader-line — 200+ строк геометрии, ломается на резких поворотах, для нашего масштаба избыточно |
| 3 | Подсветка соседних сегментов при клике | **Не делаем** | Через ymaps `MultiRoute` нетривиально (нужно лезть в `getPaths()` и менять стили каждого подсегмента + восстанавливать) |
| 4 | Кастомные HTML-маркеры | **`ymaps.templateLayoutFactory`** для numbered-маркеров и segment labels | Стандартные пресеты не дают контроля над z-index, тенями, обводкой |

## 4. Архитектура (разбиение файла)

`MapView.tsx` сейчас 446 строк. Текущие изменения добавили бы ~200–300 строк. Выносим подсистемы:

```
src/app/components/MapView.tsx               # оркестратор: загрузка, дебаунс, эффекты, состояние
src/app/components/map/
  TaskMarker.ts             # фабрика numbered Placemark + кастомный HTML layout
  SegmentLabel.ts           # фабрика плашки сегмента + кастомный HTML layout
  stackLayout.ts            # группировка совпадающих точек, расчёт offsets и якоря-ножки
  routeStyle.ts             # резолвер стиля линии (color/width/dash) по TransportMode
  segmentTransportIcon.ts   # резолвер иконки сегмента (доминирующий тип в masstransit)
  MapLegend.tsx             # HTML-оверлей с легендой (desktop ряд, mobile свернутый)
  RouteSegmentsPanel.tsx    # текущая панель из MapView, расширяется на все режимы
```

`MapView.tsx` остаётся точкой входа и хранит состояние (`transportMode`, `routeLegs`, `panelOpen`). Остальное — чистые фабрики/компоненты.

## 5. Поведение компонентов

### 5.1 TaskMarker

- Кастомный layout через `ymaps.templateLayoutFactory.createClass(...)`
- Размер: 32×32px круг
- Стиль: белая заливка, обводка `#2563eb` 2px, тень `0 1px 3px rgba(0,0,0,0.25)`
- Цифра внутри: жирная синяя (`#2563eb`), font-size 14px
- `iconOffset: [-16, -16]` — центрирование по координате
- `iconShape`: круг радиуса 16 — баллун открывается по самому маркеру
- `zIndex: 700` — выше линии маршрута и segment labels

### 5.2 Stack совпадающих точек

**Группировка:**
- Ключ группировки: `${lat.toFixed(5)}|${lon.toFixed(5)}` (порог ~1 м, согласован с текущим кодом)
- В `stackLayout.ts` функция `groupTasksByCoord(validTasks): TaskGroup[]`

**Раскладка при N>1:**
- В реальной координате — отдельный Placemark-якорь: серая точка 6×6px, `zIndex: 650`
- Над якорем — N маркеров (отдельные Placemark на той же координате), у каждого `iconOffset: [-16, -16 - 36*i]` где i = 0..N-1
- Расстояние между маркерами в стеке: 36px (32 высота + 4 зазор)
- Тонкая серая ножка 1px между якорем и нижним маркером — рисуется внутри HTML-layout якоря через `position: absolute; bottom: 0; height: 36*N px; width: 1px; background: #9ca3af`
- Каждый маркер в стеке — независимый Placemark с собственным баллуном, кликами и hint
- Стек работает в пиксельных смещениях, не зависит от зума

**Граничные случаи:**
- N=1 — без якоря и ножки, обычный TaskMarker
- N≥5 — стек растёт без ограничений (редкий случай); если возникнет — добавим коллапс позже

### 5.3 SegmentLabel

**Координата:** линейная середина сегмента `((lat1+lat2)/2, (lon1+lon2)/2)`.

**HTML-layout:**
- Прямоугольник, скругление 12px
- Белая заливка, обводка `#e5e7eb` 1px, тень `0 1px 2px rgba(0,0,0,0.15)`
- Padding 4×8, font-size 12px
- Содержимое: иконка транспорта + основной показатель + второстепенный
  - **Основной**: время если есть, иначе расстояние
  - **Второстепенный**: расстояние через `·`, серым (`#6b7280`)
  - Примеры: `🚶 12 мин · 980 м`, `🚗 6,1 км`, `М 8 мин`

**Иконка транспорта (`segmentTransportIcon.ts`):**
- `pedestrian` — `🚶`
- `auto` — `🚗`
- `masstransit` — доминирующий тип сегмента по длительности из `leg.segments`. Приоритет: `subway > rail > tram > bus > trolleybus > minibus > pedestrian`. Иконка из `TRANSPORT_TYPE_META`. Полная разбивка остаётся в `RouteSegmentsPanel`

**Чередование сторон (anti-overlap, упрощённо):**
- Чётный индекс leg → `iconOffset: [0, -14]` (плашка над линией)
- Нечётный → `iconOffset: [0, +14]` (под линией)

**Скрытие плашки:**
- Если сегмент вырожден (совпадающие координаты задач) — плашку не показываем
- Если расстояние между точками < 50 м (haversine) — плашку не показываем (на любом разумном зуме перекрыла бы маркеры)

**Z-index:** 600 — ниже numbered-маркеров (700), выше линии маршрута (~500).

**Клик:** открывает баллун с полным составом — «{Откуда} → {Куда} / Время / Расстояние / Тип».

### 5.4 routeStyle (стили линий маршрута)

| Mode | Color | Width | Style |
|---|---|---|---|
| `pedestrian` | `#16a34a` | 4 | dash `6 4` |
| `auto` | `#3b82f6` | 4 | solid |
| `masstransit` | дефолтный ymaps (фирменные цвета линий) | дефолт | дефолт |

В `routeOptions` мультироута пробрасываем `routeActiveStrokeStyle: 'dash'`/`'solid'` и `routeActiveStrokeColor`. В masstransit не переопределяем — ymaps сам красит метро/автобусы.

### 5.5 RouteSegmentsPanel (расширение)

- Сейчас открывается только в `masstransit` — расширяем на все режимы
- Заголовок панели: «Детали маршрута» (вместо «Маршрут общественного транспорта»)
- В `pedestrian/auto` — список legs, по одному пункту на leg: иконка + откуда → куда + время + расстояние
- В `masstransit` — текущая логика (подсегменты с детализацией метро/автобусов) сохраняется
- Клик по элементу панели → `map.setBounds(...)` для bounds сегмента (откуда+куда+с запасом). Реализуется через сохранённые координаты пары задач

### 5.6 MapLegend

**Позиционирование:** абсолютное поверх контейнера карты (внутри уже существующего `relative` div).

**Desktop (≥640px):**
- Внизу карты, по центру (`bottom: 12px; left: 50%; transform: translateX(-50%)`)
- Горизонтальный ряд из 4 элементов: `🚶 Пешком`, `М Метро`, `🚌 Наземный транспорт`, `🚗 Авто`
- Padding 8×12, фон `rgba(255,255,255,0.95)`, скругление 12px, тень
- `pointer-events: auto` только на самой плашке
- Ниже легенды — серая мелкая подпись «Расстояния указаны ориентировочно и могут отличаться в зависимости от выбранного маршрута»

**Mobile (<640px):**
- Кнопка-«i» 32×32 в правом нижнем углу карты
- По тапу — popover с тем же содержимым легенды (без серой подписи — на мобильном прячем второстепенное)
- Определение ширины: `window.matchMedia('(max-width: 640px)')` + listener, без новых зависимостей

### 5.7 Z-index стек

| Слой | z-index |
|---|---|
| Линии маршрута | ~500 (дефолт ymaps) |
| Якорь стека | 650 |
| SegmentLabel | 600 |
| TaskMarker | 700 |
| MapLegend (HTML, поверх карты) | 1000 (CSS) |

## 6. Что **намеренно** не делаем

- Не трогаем backend, БД, миграции, API
- Не трогаем алгоритм оптимизации
- Не вводим leaflet и другие новые библиотеки

- Не делаем leader-line от плашки к сегменту
- Не делаем подсветку соседних сегментов кликом (opacity других путей)
- Не вводим spiderfy/cluster — выбран stack
- Не ограничиваем высоту stack (риск маловероятен)

## 9. Критерии приёмки

1. Номер задачи всегда виден, не перекрывается иконками транспорта
2. Иконка транспорта показывается на сегменте между задачами, а не на маркере задачи
3. Плашка расстояния/времени не закрывает numbered-маркеры на типичных маршрутах
4. Близкие точки (< 50 м) не сливаются — плашка сегмента между ними скрывается, маркеры остаются раздельными
5. Совпадающие координаты отображаются стеком с ножкой к реальной точке
6. На карте видна легенда — что обозначают иконки и линии
7. Стиль линии маршрута отличается между pedestrian и auto (пунктир/сплошная)
8. Панель деталей маршрута открывается во всех трёх режимах
9. Не сломана существующая функциональность построения маршрута, выбора режима, сохранения и загрузки маршрута
10. Юнит-тесты на чистые функции зелёные; TypeScript+ESLint без новых ошибок

## 10. Открытые риски

- **Совместимость layout-фабрик ymaps 2.1.** Кастомные HTML-layouts — стандартный механизм ymaps 2.1, документирован. Риск минимален, но первая итерация может потребовать подгонки CSS (особенно `iconShape` для корректного открытия баллуна)
- **Производительность при N>30 задач.** Текущий код уже работает (на основной массе пользователей до 20 точек). Кастомные layouts чуть тяжелее пресетов, но в пределах нескольких процентов. Если при стресс-тесте окажется тормозно — fallback на пресеты для не-stack маркеров
- **iOS Safari fullscreenControl.** Не меняем, но HTML-оверлеи (легенда) при входе в полноэкранный режим могут не учитываться. Проверить вручную — если ломается, легенду в fullscreen прячем
