# Планировщик задач с оптимизацией маршрута

Дипломный проект: веб-приложение для планирования задач с привязкой к адресам и автоматическим построением оптимального маршрута их объезда.

## О чём этот проект

Пользователь добавляет задачи (например, «забрать посылку на Невском, 50», «встреча в офисе на Лиговском, 10»), указывает адреса, длительность и временны́е окна. Приложение само:

- определяет координаты адресов через Яндекс Карты,
- считает матрицу расстояний между точками,
- строит маршрут, который проходит все задачи с учётом времени работы каждой точки и порядка следования,
- показывает маршрут на карте с разбивкой по сегментам и видам транспорта.

Цель — сэкономить время на ручном планировании дня, когда задач много и они разбросаны по городу.

## Структура репозитория

```
diploma/
├── backend/              — REST API на Go (Clean Architecture)
├── frontend/             — SPA на React + Vite
│   └── Task Planning App/
├── Диплом Latex/         — текст пояснительной записки (LaTeX, ГОСТ 7.32)
├── docs/                 — вспомогательная документация
├── schemes/              — схемы и диаграммы
├── ya_docs/              — выгрузки документации Яндекс Карт
├── Источники/            — материалы для библиографии
└── CLAUDE.md             — подробный гид по архитектуре для ИИ-ассистента
```

### Backend (`backend/`)

Go 1.23, Gin, PostgreSQL 16 + PostGIS, JWT-аутентификация.

Основные точки входа:

- `cmd/api/main.go` — запуск HTTP-сервера
- `internal/api/http/` — роуты, хендлеры, DTO, middleware
- `internal/domain/` — бизнес-логика по доменам: `auth`, `task`, `route`, `taskimport`
- `internal/domain/route/optimizer/` — алгоритм построения маршрута (NNH-TW: жадный «ближайший сосед» с учётом временных окон и приоритетов)
- `internal/platform/postgres/` — репозитории и пул соединений
- `internal/platform/distance/` — провайдер расстояний (OSRM) с in-memory LRU-кэшем
- `migrations/` — миграции БД

### Frontend (`frontend/Task Planning App/`)

React 18, TypeScript, Vite 6, Tailwind CSS 4, shadcn/ui.

- `src/app/components/` — экраны и компоненты: список задач, форма, карта, импорт CSV/XLSX
- `src/app/components/MapView.tsx` — карта на Яндекс Maps JS API 2.1: маркеры, сегменты маршрута, выбор вида транспорта
- `src/app/api/client.ts` — клиент REST API с авто-рефрешем токена при 401
- `src/app/context/auth-context.tsx` — сессия пользователя в `localStorage`
- `src/app/utils/routeOptimizer.ts` — построение матрицы расстояний через Яндекс
- `src/app/hooks/` — хуки: автокомплит адресов, оптимизация маршрута, экспорт задач

### Текст диплома (`Диплом Latex/`)

Пояснительная записка по ГОСТ 7.32 (`G7-32.cls`). Главный файл — `rpz.tex`, главы пронумерованы (`12-intro.tex`, `20-analysis.tex` и т.д.). Сборка через `latexmk`. Диаграммы: PNG в `images/`, исходники PlantUML в `images/plantUML/`, скрипты графиков на Python в `images/python/`.

## Как запустить

### 1. Backend (через Docker)

```bash
cd backend
docker compose up --build
```

Поднимает PostgreSQL на 5432, прогоняет миграции, запускает API на `http://localhost:8080`.

Без Docker:

```bash
cd backend
cp .env.example .env       # вписать APP_DB_DSN, APP_JWT_SECRET
make run
```

### 2. Frontend

```bash
cd "frontend/Task Planning App"
pnpm install
pnpm dev
```

Откроется на `http://localhost:5173`. Запросы к `/api/*` проксируются на backend.

В файле `frontend/Task Planning App/.env.local` нужен ключ Яндекс Карт:

```
VITE_YANDEX_GEOCODER_KEY=<ваш_ключ>
```

После изменения `.env.local` — перезапустить dev-сервер.

## Как этим пользоваться

1. Открыть `http://localhost:5173`, зарегистрироваться.
2. Добавить задачи вручную или импортировать список из CSV/XLSX.
3. Для каждой задачи указать адрес (подсказки приходят из Яндекса), при необходимости — длительность и временно́е окно.
4. Нажать «Оптимизировать маршрут», выбрать вид транспорта (пешком / общественный / авто).
5. Получить порядок объезда, тайминги по каждой точке и визуализацию на карте.
6. Сохранённые маршруты доступны в боковой панели; их можно переименовывать и удалять.
