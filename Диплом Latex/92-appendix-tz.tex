\section*{В.1 Общие сведения}

Полное наименование системы: веб-приложение для автоматизированного планирования маршрутов с учетом временных окон. Условное обозначение~\textendash{} <<Планировщик маршрутов>>. Организация-разработчик~\textendash{} Московский политехнический университет.

Основание для разработки~\textendash{} задание на выпускную квалификационную работу. Плановые сроки: февраль~\textendash{} май 2026~года. Прямое финансирование не предусмотрено.

Результаты передаются заказчику в виде пояснительной записки, исходного кода (репозиторий Git) и собранного дистрибутива (Docker-образ серверной части, статическая сборка клиентской части).

\section*{В.2 Назначение и цели создания системы}

Назначение. Автоматизированное построение оптимальной последовательности выполнения задач с учетом географического положения точек, временных окон обслуживания и длительности выполнения каждой задачи.

Цели:

\begin{compactlist}
  \item сокращение времени ручного планирования маршрута с временными окнами;
  \item уменьшение числа нарушений временных окон за счет автоматизированной проверки допустимости;
  \item доступность инструментов оптимизации маршрута для частных пользователей и малого бизнеса без коммерческой подписки.
\end{compactlist}

\section*{В.3 Характеристика объекта автоматизации}

Объект автоматизации~\textendash{} процесс планирования последовательности выполнения задач пользователя в городской среде. В отсутствие специализированного программного обеспечения планирование выполняется вручную; при увеличении числа задач трудоемкость возрастает нелинейно, а вероятность нарушения временных ограничений увеличивается.

Целевая аудитория: частные пользователи, специалисты на выезде, курьеры малого бизнеса, индивидуальные предприниматели, диспетчеры.

\section*{В.4 Требования к системе}

\subsection*{В.4.1 Требования к системе в целом}

Система реализуется в виде клиент-серверного веб-приложения и состоит из серверной части (хранение данных, бизнес-логика, алгоритмы оптимизации) и клиентской части (взаимодействие с пользователем через веб-браузер).

Численность пользователей~\textendash{} до 100 одновременных. Режим функционирования~\textendash{} непрерывный с допустимыми технологическими перерывами. Время отклика интерфейса не превышает 2~секунд при нагрузке до 5~запросов в секунду.

Надежность~\textendash{} сохранение работоспособности при кратковременной недоступности внешнего картографического сервиса за счет кэширования. Эргономика~\textendash{} адаптивный интерфейс для устройств с диагональю экрана от 4 до 32~дюймов. Безопасность~\textendash{} хранение паролей в виде хэш-значений \texttt{bcrypt}, токенов обновления~\textendash{} SHA-256; передача данных по HTTPS.

\subsection*{В.4.2 Требования к функциям}

Система должна реализовать:

\begin{compactlist}
  \item регистрацию и аутентификацию пользователей по электронной почте и паролю;
  \item создание, редактирование, удаление и клонирование задач с указанием адреса, длительности и временного окна;
  \item импорт и экспорт перечня задач в форматах CSV и XLSX;
  \item геокодирование адресов через внешний сервис картографии;
  \item построение матрицы расстояний между адресами задач;
  \item автоматизированное вычисление оптимальной последовательности с учетом временных окон;
  \item дополнительные ограничения: фиксация начальной и конечной точки маршрута, попарные ограничения порядка;
  \item расчет времени прибытия, ожидания и завершения обслуживания для каждой остановки;
  \item визуализацию маршрута на карте, обнаружение конфликтов временных окон;
  \item выбор способа перемещения (автомобиль, пешеход, общественный транспорт).
\end{compactlist}

\subsection*{В.4.3 Требования к видам обеспечения}

Информационное обеспечение~\textendash{} СУБД PostgreSQL~16; структура управляется механизмом миграций.

Программное обеспечение серверной части~\textendash{} Docker Engine 24.0 и выше, Docker Compose 2.0 и выше (Linux, macOS или Windows).

Программное обеспечение клиентской части~\textendash{} веб-браузер с поддержкой JavaScript ES2020 (Chrome~90+, Firefox~88+, Safari~14+, Edge~90+, Yandex Browser~25+).

Техническое обеспечение серверной части~\textendash{} процессор не ниже 1~ГГц, ОЗУ не менее 512~МБ, дисковое пространство не менее 1~ГБ, соединение с сетью Интернет.

Лингвистическое обеспечение~\textendash{} язык пользовательского интерфейса~\textendash{} русский.

\section*{В.5 Состав и содержание работ по созданию системы}

\begin{compactlist}
  \item анализ предметной области, формирование требований;
  \item проектирование архитектуры и модели данных;
  \item выбор алгоритма оптимизации маршрута;
  \item реализация серверной части (REST API, бизнес-логика, репозитории);
  \item реализация клиентской части (интерфейс, интеграция с картографией);
  \item модульное и нагрузочное тестирование;
  \item подготовка эксплуатационной документации.
\end{compactlist}

\section*{В.6 Порядок контроля и приемки}

Приемка осуществляется в форме защиты выпускной квалификационной работы перед государственной экзаменационной комиссией: демонстрация работы системы на типовом сценарии, проверка выполнения функциональных и нефункциональных требований, проверка отчета о нагрузочном тестировании.

\section*{В.7 Требования к составу и содержанию работ по подготовке объекта автоматизации}

Для ввода системы в действие необходимо:

\begin{compactlist}
  \item обеспечить сервер с Docker Engine 24.0+ и Docker Compose 2.0+;
  \item получить ключ доступа к Яндекс JavaScript API;
  \item установить секретный ключ для подписи JWT-токенов (не менее 32~символов);
  \item сконфигурировать список допустимых источников CORS;
  \item обеспечить резервное копирование данных PostgreSQL средствами \texttt{pg\_dump}.
\end{compactlist}
