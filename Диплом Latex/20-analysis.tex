\section{Исходное состояние объекта и характеристика предметной области}

Объектом исследования в рамках данной работы является процесс
планирования последовательности выполнения задач в городской
среде с учетом их пространственного расположения и временных ограничений.

В настоящее время большинство пользователей решают задачу планирования
маршрута вручную. Типичный сценарий включает формирование списка дел в
менеджере задач, последующий поиск адресов в навигационном сервисе и
самостоятельное определение порядка посещения точек. При наличии временных
окон (например, «с 9:00 до 12:00») пользователь вынужден дополнительно сопоставлять время перемещения и длительность выполнения задачи.

Существующие цифровые инструменты можно разделить на две группы:
\begin{itemize}
  \item менеджеры задач (не учитывают пространственный фактор);
  \item навигационные сервисы (не работают с временными окнами и списками задач).
\end{itemize}

Таким образом, пользователь вынужден использовать несколько инструментов одновременно,
что увеличивает трудозатраты и повышает вероятность ошибок.

Целевой аудиторией системы являются:

\begin{itemize}
  \item частные пользователи, планирующие личные дела в городе;
  \item мастера и специалисты на выезде;
  \item курьеры малого бизнеса;
  \item индивидуальные предприниматели;
  \item диспетчеры, формирующие небольшие маршруты вручную.
\end{itemize}

Особенностью данной предметной области является необходимость одновременного учета:
\begin{itemize}
  \item географического расположения объектов;
  \item временных ограничений;
  \item длительности выполнения задач;
  \item минимизации времени перемещения и ожидания.
\end{itemize}

Таким образом, предметная область представляет собой систему с признаками логистической оптимизации, однако в упрощенном масштабе, ориентированном на одного пользователя или малый бизнес.

\section{Постановка проблемы и формирование цели разработки}

Анализ исходного состояния показал, что основной проблемой является отсутствие доступного инструмента, объединяющего управление задачами и автоматическую маршрутизацию с учетом временных окон.

Ручной подход:

\begin{itemize}
  \item требует значительных временных затрат;
  \item не гарантирует оптимальность маршрута;
  \item становится неэффективным при увеличении числа точек;
  \item не обеспечивает формализованного учета временных ограничений.
\end{itemize}

Целью разработки является создание веб-приложения, обеспечивающего
автоматизированное формирование оптимального маршрута выполнения задач
с учетом их географического положения, временных окон и длительности выполнения.

Назначение продукта заключается в цифровой трансформации процесса ручного планирования
маршрута в автоматизированный процесс.

На основании цели сформирован следующий перечень функций:

\begin{itemize}
  \item создание, редактирование и удаление задач;
  \item хранение географических координат;
  \item получение матрицы расстояний через внешние API;
  \item вычисление оптимальной последовательности выполнения задач;
  \item расчет времени прибытия, ожидания и завершения;
  \item визуализация маршрута на карте;
  \item экспорт маршрута в формате JSON.
\end{itemize}

Для обеспечения соответствия назначению определены следующие нефункциональные требования:

\begin{itemize}
  \item время ответа сервера — не более 2 секунд при типовой нагрузке;
  \item поддержка современных браузеров;
  \item масштабируемость до 100 одновременных пользователей;
  \item устойчивость к повторным запросам внешних API за счет кэширования.
\end{itemize}

\section{Обоснование выбора технологий и платформ}

\subsection{Выбор серверной платформы}

В качестве языка для написания серверной части был выбран Golang\cite{golang}.

Выбор языка Golang\cite{golang} обусловлен:

\begin{itemize}
  \item статической типизацией, снижающей риск ошибок;
  \item встроенной моделью конкурентности;
  \item наличием практического опыта разработки.
\end{itemize}

\subsection{Выбор СУБД и работы с геоданными}

В качестве СУБД выбрана PostgreSQL\cite{PostgreSQL}.

Обоснование выбора:

\begin{itemize}
  \item наличие геометрических индексов (GiST\cite{PostgreSQL_gist});
  \item высокая надежность и зрелость платформы;
  \item наличием практического опыта разработки.
\end{itemize}

\subsection{Выбор клиентских технологий}

Для реализации пользовательского интерфейса был выбран React\cite{react}.

Причины выбора:

\begin{itemize}
  \item компонентный подход к разработке;
  \item развитая экосистема;
  \item наличие поддержки картографических библиотек.
\end{itemize}

\subsection{Итоговый технологический стек}

Итоговый выбор технелогического стека для разработки системы:

\begin{itemize}
  \item Backend: Golang;
  \item Frontend: React;
  \item СУБД: PostgreSQL;
  \item Контейнеризация: Docker\cite{docker}.
\end{itemize}

\section{Обзор аналогов и сравнительный анализ}

В качестве аналогов были рассмотрены Relog \cite{relog} , Яндекс Маршрутизация \cite{yandex_routing} и Spoke \cite{spoke}.

Для оценки выбраны критерии:

\begin{itemize}
  \item целевой сегмент;
  \item модель оплаты;
  \item поддержка пешеходных маршрутов;
  \item наличие русского языка;
  \item ориентация на малый бизнес и частных пользователей.
\end{itemize}

Проведенный анализ в таблице \ref{tab:analyze_analogs} показал, что существующие решения ориентированы преимущественно на корпоративный сектор и управление автопарками.
Их функциональность избыточна для частных пользователей и малого бизнеса, а стоимость делает их экономически нецелесообразными
для небольшого количества ежедневных задач.

\section{Выводы}

Проведен анализ предметной области, выявлены ограничения существующих инструментов и обоснована актуальность разработки системы
планирования маршрутов с учетом временных окон. Сформулирована цель и назначение продукта, определен перечень функций и
нефункциональных требований.

На основании сравнительного анализа технологий выбран стек разработки,
обеспечивающий требуемую производительность и масштабируемость системы.
Проведенный анализ аналогов подтвердил целесообразность создания специализированного решения,
ориентированного на частных пользователей и малый бизнес.
